Create a production-ready React component named `SupplierPerformance` for a procurement dashboard.

## Objective

Build a responsive "Supplier Performance" widget that allows users to quickly compare supplier performance using:

1. On-time delivery percentage.
2. Average response time to purchase orders.
3. A color-coded performance status: Green, Yellow, or Red.

## Technology Requirements

* Use React functional components and modern React patterns.
* Use JavaScript or TypeScript; prefer TypeScript if type definitions are needed.
* Use semantic HTML and accessible UI elements.
* Keep the component self-contained and reusable.
* Do not hard-code supplier records; all supplier data must come through props/API data.
* Use clear, maintainable component and variable names.
* Handle loading, empty, and error states gracefully.
* Make the layout responsive for desktop, tablet, and mobile screens.

## Component API

Create the component with an API similar to:

```tsx
interface Supplier {
  id: string;
  name: string;
  onTimeDeliveryPercentage: number;
  averageResponseTimeHours: number;
}

interface SupplierPerformanceProps {
  suppliers: Supplier[];
  loading?: boolean;
  error?: string | null;
}
```

The component should be usable as:

```tsx
<SupplierPerformance
  suppliers={[
    {
      id: "supplier-1",
      name: "Acme Supplies",
      onTimeDeliveryPercentage: 96,
      averageResponseTimeHours: 3.5
    },
    {
      id: "supplier-2",
      name: "Global Parts",
      onTimeDeliveryPercentage: 82,
      averageResponseTimeHours: 10
    }
  ]}
/>
```

Assume that the API returns an array of supplier objects matching this structure:

```json
{
  "id": "string",
  "name": "string",
  "onTimeDeliveryPercentage": 0,
  "averageResponseTimeHours": 0
}
```

## UI Layout

Create a dashboard card titled "Supplier Performance".

Use a responsive table as the primary layout. Each supplier should appear as one row with these columns:

* Supplier
* On-Time Delivery
* Avg. PO Response
* Status

For the "On-Time Delivery" column, display the percentage prominently and optionally include a small progress bar.

For "Avg. PO Response", display the response time in hours, using a readable format such as `3.5 hrs`.

For "Status", display a colored badge containing the appropriate status label and, where appropriate, a small status indicator.

On smaller screens, make the table horizontally scrollable or transform rows into compact supplier cards without losing any information.

## Color-Coding Logic

Determine the supplier status using the following rules:

### Green — Good

Use Green when:

* On-time delivery percentage is `>= 90%`, AND
* Average PO response time is `<= 4 hours`.

### Yellow — Needs Attention

Use Yellow when the supplier does not qualify for Green but:

* On-time delivery percentage is `>= 75%`, AND
* Average PO response time is `<= 12 hours`.

### Red — Poor

Use Red when either:

* On-time delivery percentage is `< 75%`, OR
* Average PO response time is `> 12 hours`.

The status calculation must be implemented in a reusable helper function rather than duplicated throughout the JSX.

Use accessible color choices and do not rely on color alone to communicate status. Include the text label (`Good`, `Needs Attention`, or `Poor`) and, if useful, an icon or accessible status indicator.
